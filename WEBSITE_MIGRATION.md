Статус: подготовлено в черновиках, в рабочую версию не включено.
Apps Script для работы нового кода не нужен. Старые файлы с
confirmOwletSharedWriteReady и общими обёртками устанавливать не следует.

## Расписание без Apps Script

Есть команды `python native_jobs.py morning|evening|statistics|sync|quests|cleanup`.
`--dry-run` печатает план без импорта бота и побочных действий.
Нативные задания можно вызвать существующим внешним cron на Render/сервере.
Дополнительно подготовлен GitHub Actions relay `.github/workflows/native-schedule.yml`.
Он НЕ активен, пока repository variable NATIVE_SCHEDULES_ENABLED не равна true.
Для его использования владелец добавляет GitHub secret OWLET_SCHEDULE_SECRET,
совпадающий с SCHEDULE_SECRET в Render. Значения секретов в чат/код не помещать.

Подтверждённый план сохранён в `native_schedule.json` и читается из файла.
Render NATIVE_SCHEDULES_JSON при наличии переопределяет его (значение `[]`
отключает задания). Relay по-прежнему выключен до явного включения.

```json
[{"job":"sync","everyMinutes":240},
 {"job":"statistics","weekdays":[4,5,6,0],"hour":18,"minute":0}]
```

Дни: понедельник=0, воскресенье=6. Часовой пояс STATS_TIMEZONE, по умолчанию
Europe/Moscow. Relay проверяет задания раз в пять минут; GitHub может задерживать
cron. Для дневных отправок предусмотрено окно до 30 минут. Точное выполнение
в секунду не гарантируется. Частотные задания используют интервалы от пяти минут.
Запуск фиксируется в _NativeJobs до побочных действий. После сбоя/рестарта
незавершённый запуск автоматически не повторяется: нужна проверка оператором,
чтобы не отправить повторное объявление. Это осознанная граница первой версии.

## Порядок переключения

1. Резервные копии всех трёх книг и старых deployments; проверить текущие данные.
2. Подтвердить расписание, добавить ID книги квестов, проверить Editor-доступ.
3. Согласовать финальный diff и окно переключения с владельцем.
4. Приостановить Google-триггеры и старые пишущие Web App; дождаться окончания
   текущих запросов/выдач. Не запускать ручные Apps Script одновременно с Python.
   Если ранее опубликованы ошибочные обёртки, до переключения вернуть прежние deployments.
5. Развернуть новый бот и выполнить preflight. Затем — один согласованный отчёт,
   повтор того же requestId, синхронизацию, preview бонуса, dryRun квеста, коллекции.
   Нельзя выдавать реальные тестовые артефакты или сообщения без согласованного примера.
6. Опубликовать mouses, затем отдельный сайт сокровищницы. Убедиться, что сетевых
   запросов к script.google.com нет. Проверить вход обычным и административным паролем.
7. Включить подтверждённое расписание во внешнем cron; проверить отсутствие
   параллельных старых триггеров. После проверки старые deployments можно отключить.

## Сохранение состояния и ограничения

Имена берутся из живого листа «Участники» и беседы VK, INITIAL_PEOPLE не используется.
Новая неделя создаётся в Python; пустая строка участника дополняется синхронизацией/привязкой.
Отчёты ушедших участников текущей недели сохраняются. Существующие EventLog,
ChatLog, _ArtifactDrops, Инвентарь, колонка I бонусных кампаний и состояния квестов
не пересоздаются и не сбрасываются. Script Properties старых обработанных отчётов
нельзя прочитать Sheets API: переключаться после завершения старых запросов;
при необходимости отдельно экспортировать старый временный журнал до выключения.

Запись отчёта и requestId выполняются атомарно; инвентарь и результат броска тоже.
Одинаковый requestId с другим содержимым отклоняется. Шанс: 10% ниже плана,
20% при выполнении, только при увеличении факта. Редкости 65/22/9/3/1.
При неподтверждённом уведомлении сайт сохраняет requestId для повторного нажатия.
Дедупликация VK ограничена правилами VK; бесконечная exactly-once гарантия
между внешними сервисами не заявляется. Фонового возобновления отчётов сайта нет.

Google metadata lock с ID 1937152401 теперь нужен только для сериализации Python
workers/instances. При timeout/5xx записи он сохраняется до проверки оператором;
это предотвращает запись поверх неизвестного результата. Не снимать его по таймеру.
API чтения сайта сохраняет readonly scope; запись использует отдельную сессию.
Кеш статистики может оставаться старым до пяти минут в другом worker.

## Проверки и откат

`PYTHONPATH=. python -m unittest discover -s tests -v`

Для mouses: `node --check app.js`, `node --check treasury.js`,
`node tests/statistics.cjs`, `node tests/records.cjs`.
Для отдельной сокровищницы: `node --check app.js`.
Все автоматические проверки выполняются без реальных записей и отправки VK.

Откат: выключить внешний cron и приём новых записей, дождаться завершения запросов,
вернуть старый бот/сайт и прежние deployments. Журналы, отчёты и награды не удалять.
Не включать старые писатели параллельно с новым ботом.
