# Квесты с кнопками под сообщением Робосычика

Робосычик публикует этап с 2–6 кнопками вариантов. Участник нажимает кнопку,
бот сохраняет один голос на его VK ID. До дедлайна можно изменить выбор.
После дедлайна бот считает голоса, объявляет результат и продолжает ветку.

Кнопки используют стандартное действие VK `text`: нажатие отправляет в чат
название варианта и технический payload. Робосычик подтверждает принятый голос.
Это клавиатура под сообщением, не встроенный опрос VK. Подписывать новое
событие `message_event` не требуется: используется уже подключённое `message_new`.

## Подключение

Пользовательский токен, приложение VK ID, бизнес-профиль и OAuth **не нужны**.
Созданное приложение VK ID для этой функции не используется. Callback-адрес
`/vk-id/callback` на Netlify настраивать не требуется. `VK_POLL_USER_TOKEN`
не нужен; существующий `VK_TOKEN` сообщества оставьте прежним.

Нужны только существующие настройки:

| Настройка | Значение |
|---|---|
| `VK_TOKEN` | Прежний токен сообщества с доступом к сообщениям |
| `QUEST_SPREADSHEET_ID` | ID «Книги приключений» |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Прежний сервисный аккаунт с доступом редактора к книге |
| `NATIVE_STORAGE_ENABLED` | `true` |

В листе «Этапы» добавьте справа колонки `варианты_JSON` и `ничья_этап`, если
их ещё нет. Остальные колонки не переименовывайте и не переставляйте.
Лист «Голоса» бот создаёт сам. В первом запуске он должен отсутствовать либо
иметь ровно заголовки из раздела «Хранение». Старые экспериментальные листы
не стирайте: переименуйте и сохраните отдельно, если их схема отличается.

После объединения PR и деплоя `/` должен показывать `questVotingVersion: 3`.
Проверка без отправки: защищённый `POST /quest-tick` с `{"dry_run":true}` и
заголовком `X-Schedule-Secret`. Для запуска подготовьте квест с будущим
дедлайном, установите `active`, затем GitHub Actions → Run workflow → `quests`.
Первое живое нажатие и сохранение в рабочей книге ещё нужно проверить после деплоя.

Планировщик проверяет квесты раз в час на 17-й минуте. GitHub Actions может
задержать запуск, поэтому публикация и итоги не гарантированы до минуты.
Бот не принимает нажатия после дедлайна, даже если итог ещё не опубликован.
Давайте достаточно времени между активацией и дедлайном (больше часа).
Если `QUEST_SPREADSHEET_ID` не задан, журнал явно сообщает причину пропуска.

## Пример первого голосования

Не запускайте пример, пока не зададите настоящий будущий дедлайн и текст.
На каждый новый запуск истории используйте **новый quest_id**. Этапы внутри
одного квеста должны иметь уникальные ID; циклы с повторным входом в уже
проведённое голосование не поддерживаются.

Лист «Квесты» сохраняет прежние колонки:

| quest_id | название | статус | текущий_этап | peer_id | описание |
|---|---|---|---|---|---|
| forest01 | Развилка | draft | choice | 2000000002 | Выбор пути |

Когда всё готово, замените `draft` на `active`. Для запуска без голосования
по-прежнему используется этап `start` и прежние пороги.

В листе «Этапы» нужны три строки:

| Поле | Голосование | Ветка леса | Ветка гор |
|---|---|---|---|
| quest_id | forest01 | forest01 | forest01 |
| stage_id | choice | forest | mountains |
| тип | vote | finish | finish |
| текст | Сычики встретили развилку. Куда идём? | Сычики отправились в лес. | Сычики выбрали горную тропу. |
| порог_мышей | пусто | пусто | пусто |
| порог_процентов | пусто | пусто | пусто |
| дедлайн_ISO | будущая дата с часовым поясом | пусто | пусто |
| успех_этап | пусто | пусто | пусто |
| провал_этап | mountains | пусто | пусто |
| варианты_JSON | JSON ниже | пусто | пусто |
| ничья_этап | пусто | пусто | пусто |

`варианты_JSON`:

```json
[{"текст":"Пойти в лес","этап":"forest"},{"текст":"Подняться в горы","этап":"mountains"}]
```

Дедлайн, например: `2026-11-20T18:00:00+03:00` (замените на нужный).

## Голоса, итоги и продолжение

- Голос принадлежит пользователю из события VK, а не ID из данных кнопки.
  Кнопка должна соответствовать текущему квесту, этапу, чату и версии настроек.
- Один голос на пользователя и этап. Повторное нажатие меняет выбор.
  Повторная доставка старого сообщения не добавляет голос и не отменяет новый.
- Нажатие после дедлайна, в другой беседе, на старом этапе или на старой
  версии кнопки отклоняется. Обычный текст без payload не считается голосом.
- На кнопке до 40 символов. Длинная подпись сокращается, но полный текст
  варианта остаётся в объявлении; номера помогают различать варианты.
- Выигрывает вариант с наибольшим количеством голосов. При ничьей выбирается
  `ничья_этап`, если он задан. Иначе первый из лидирующих вариантов в JSON.
  Это правило заранее публикуется в объявлении.
- При отсутствии голосов используется обязательный `провал_этап`. Если
  отправка объявления не подтверждена до дедлайна, бот останавливает переход,
  чтобы не принять технический сбой за отсутствие голосов.
- Тип `finish` завершает квест. Обычный этап продолжает историю по своим
  порогам и дедлайну; затем можно открыть голосование с новым stage_id.
  Два голосования непосредственно подряд не поддерживаются.
- Старые кнопки остаются видимыми в старом сообщении, но больше не принимаются.
  Автоматическое удаление клавиатуры с уже опубликованного сообщения не добавлено.

## Хранение

Точное содержимое заголовков листа «Голоса»:

```text
quest_id | stage_id | peer_id | vk_id | choice | message_id | updated_ISO | revision
```

Записи обновляются под блокировкой книги. Подсчёт использует последнее
сообщение пользователя по conversation_message_id. Итоги публикуются без
списка голосовавших. Опрос не анонимный для участников беседы: выбранный
вариант виден в отправленном кнопкой сообщении.

Не меняйте вопрос, варианты, ветки, чат и дедлайн после запуска. При смене
настроек старые кнопки перестают действовать; при несовпадении версии уже
сохранённых голосов итог останавливается, чтобы не выбрать неверную ветку.
Используйте новый stage_id для нового голосования, новый quest_id — для
повторного запуска истории. Циклы с переоткрытием завершённого голосования
запрещены. Служебные листы и записи исходящих не удаляйте.

Объявления с кнопками отправляются со стабильным random_id на событие квеста,
чтобы повтор отправки использовал тот же ключ VK. При ошибке отправки событие
остаётся в «Исходящие» до подтверждения. Обычные сюжетные сообщения используют
прежний механизм очереди и могут повториться при неопределённом сетевом сбое.


## Занятая книга

Операции квестов повторяют попытку получить занятый замок до пяти раз с
короткой возрастающей задержкой. Повторяется только Busy до начала операции;
таймаут или неопределённый результат записи не повторяется автоматически.
Любой HTTP 400 больше не считается занятостью: проверяется сообщение о
существующем metadataId либо фактический замок этого приложения.

Если после повторов книга остаётся занятой, голос не подтверждается. Можно
повторить нажатие позже. При устойчивой блокировке нужна проверка незавершённой
операции: не удаляйте developerMetadata и не сбрасывайте замок наугад. Автоматическое
удаление чужого или сохранённого после неопределённой записи замка не добавлено.
Маркер развёрнутого исправления в /health: questLockRetryVersion: 1.
