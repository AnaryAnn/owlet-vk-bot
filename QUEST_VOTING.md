# Квесты с голосованием

Участники голосуют сообщениями в той же беседе VK: `голос forest01 1`.
Можно также написать команду после упоминания Робосычика. Это голосование
сообщениями, а не встроенный опрос VK. Не нужны новые права VK API.

У каждого положительного VK ID один голос на этап. Новое сообщение меняет
выбор; повтор старого события не перезаписывает новый голос. Голосовать
можно только в беседе квеста, когда он в состоянии `running` и текущий этап
имеет тип `vote`. В момент дедлайна приём закрывается, даже если планировщик
ещё не подвёл итог. ID участников в итоговом сообщении не публикуются.

## Подключение

1. В Render должен быть `QUEST_SPREADSHEET_ID`: ID существующей «Книги приключений».
   Сервисному аккаунту Google нужен доступ редактора к этой таблице.
   Используется прежний `GOOGLE_SERVICE_ACCOUNT_JSON` и `NATIVE_STORAGE_ENABLED=true`.
2. В листе «Этапы» добавьте справа колонки `варианты_JSON` и `ничья_этап`.
   Существующие колонки не переименовывайте и не переставляйте.
3. Разверните последний коммит на Render. Проверка `/` должна показывать
   `questVotingVersion: 1`.
4. Заполните квест и его этапы. Проверьте сначала через защищённый
   `POST /quest-tick` с `{"dry_run":true}` и заголовком `X-Schedule-Secret`.
   Dry run проверяет переходы без отправки сообщений и изменения состояния.
5. В GitHub Actions → «Расписание Робосычика без Apps Script» → Run workflow
   выберите `quests`. Это начнёт активные квесты и отправит их объявления.

Планировщик вызывает `quests` раз в час, на 17-й минуте. При задержке GitHub
Actions итоги появятся позже; голоса после дедлайна всё равно не принимаются.
Если книга не задана, журнал явно сообщает о пропуске с причиной.
Секрет расписания и `NATIVE_SCHEDULES_ENABLED=true` используются прежние.

## Пример первого голосования

Не запускайте пример, пока не зададите настоящий будущий дедлайн и текст.
На каждый новый запуск истории используйте **новый quest_id**. Этапы внутри
одного квеста должны иметь уникальные ID; циклы с повторным входом в уже
проведённое голосование не поддерживаются.

Лист «Квесты» сохраняет прежние колонки:

| quest_id | название | статус | текущий_этап | peer_id | описание |
|---|---|---|---|---|---|
| forest01 | Развилка | draft | choice | 2000000002 | Выбор пути |

Когда всё готово, замените `draft` на `active`. Для запуска без голосования
по-прежнему используется этап `start` и прежние пороги.

В листе «Этапы» нужны три строки:

| Поле | Голосование | Ветка леса | Ветка гор |
|---|---|---|---|
| quest_id | forest01 | forest01 | forest01 |
| stage_id | choice | forest | mountains |
| тип | vote | finish | finish |
| текст | Сычики встретили развилку. Куда идём? | Сычики отправились в лес. | Сычики выбрали горную тропу. |
| порог_мышей | пусто | пусто | пусто |
| порог_процентов | пусто | пусто | пусто |
| дедлайн_ISO | будущая дата с часовым поясом | пусто | пусто |
| успех_этап | пусто | пусто | пусто |
| провал_этап | mountains | пусто | пусто |
| варианты_JSON | JSON ниже | пусто | пусто |
| ничья_этап | пусто | пусто | пусто |

`варианты_JSON`:

```json
[{"текст":"Пойти в лес","этап":"forest"},{"текст":"Подняться в горы","этап":"mountains"}]
```

Дедлайн, например: `2026-11-20T18:00:00+03:00` (замените на нужный).

## Результат и продолжение

- 2–8 вариантов. Команда участника использует номер варианта от 1.
- Выигрывает вариант с наибольшим количеством голосов.
- При ничьей выбирается `ничья_этап`, если он задан. Иначе первый из
  лидирующих вариантов по порядку в JSON. Правило указано в объявлении.
- Если голосов нет, выбирается обязательный `провал_этап`.
- Итог содержит количество голосов по каждому варианту и текст новой ветки.
- Тип `finish` завершает квест. Любой обычный этап продолжает квест с его
  порогами и дедлайном. После такого этапа можно открыть новое голосование
  с отдельным `stage_id`; два голосования непосредственно подряд не поддерживаются.

Лист «Голоса» создаётся автоматически при первом голосе, со столбцами
`quest_id, stage_id, peer_id, vk_id, choice, message_id, updated_ISO`.
Операции выполняются под общей блокировкой книги. Переходы и объявления
сохраняются одним batch в прежних «Квесты», «Исходящие» и «Журнал».
Не удаляйте служебные листы и записи исходящих при повторных запусках.
При сетевой ошибке после приёма сообщения VK, но до отметки отправки в
таблице, повтор объявления возможен; голоса от этого не дублируются.
