# Квесты со встроенными опросами VK

Робосычик создаёт стандартный опрос VK, прикрепляет его к сообщению в беседе,
после дедлайна читает итоги из VK и продолжает победившую сюжетную ветку.
Команды голосования сообщениями удалены. Опрос анонимный, с одним ответом,
возможностью переголосовать и автоматическим закрытием в заданное время.
Нельзя ограничить голосование только участниками беседы: учитываются итоги
VK, включая голоса других людей, получивших доступ к опросу.

## Статус проверки

Код и работа с API проверены тестами с подставными ответами VK. Реальное
создание и прикрепление в рабочую беседу **ещё не проверены**: нужен
пользовательский токен. Само наличие `poll` в официальной схеме вложений
не гарантирует доступ конкретного токена и доступность опроса для бота.
Отправка подтверждается через `messages.getById`: без нужного poll-вложения
объявление не помечается отправленным, а ветка не выбирается.

Официальная схема API 5.199:
- https://github.com/VKCOM/vk-api-schema/blob/master/polls/methods.json
- https://github.com/VKCOM/vk-api-schema/blob/master/messages/objects.json
- https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json

## Что добавить в Render

Откройте сервис Робосычика → Environment → Edit / Add Environment Variable:

| Имя | Значение |
|---|---|
| `VK_POLL_USER_TOKEN` | Пользовательский access token VK API, доступный для `polls.create` и `polls.getById` |
| `QUEST_SPREADSHEET_ID` | ID существующей «Книги приключений», если он ещё не задан |

Существующий `VK_TOKEN` сообщества **не заменять**. Он используется для
отправки сообщений от имени Робосычика и проверки вложений.
Новый токен применяется только к `polls.create` / `polls.getById` и хранится
в окружении Render. Не вставляйте токены в чат, таблицы, GitHub, URL или логи.
Получайте пользовательский токен через официальную авторизацию собственного
приложения VK. Ключ сообщества, сервисный ключ и `id_token` не подходят.
Доступность нужных методов и срок жизни зависят от авторизации приложения;
текущая реализация не обновляет истёкший пользовательский токен автоматически.
При ошибке авторизации замените его в Environment. Готовые чужие приложения
и сайты для извлечения токенов не требуются и не рекомендуются.

Сервисному аккаунту Google нужен доступ редактора к книге. Используются
прежние `GOOGLE_SERVICE_ACCOUNT_JSON` и `NATIVE_STORAGE_ENABLED=true`.
В листе «Этапы» добавьте справа колонки `варианты_JSON` и `ничья_этап`.
Остальные колонки не переименовывайте и не переставляйте.

После объединения PR и деплоя `/` должен показывать `questVotingVersion: 2`.
Dry run: защищённый `POST /quest-tick` с `{"dry_run":true}` и заголовком
`X-Schedule-Secret`. Он не создаёт опросы и не проверяет реальную отправку VK.
Для первого живого запуска подготовьте квест с будущим дедлайном,
установите `active`, затем GitHub Actions → Run workflow → `quests`.
Проверьте опрос в беседе перед использованием реального сюжета.

Планировщик вызывает `quests` раз в час на 17-й минуте. GitHub может задержать
запуск, поэтому публикация и итоги не гарантированы до минуты. VK закрывает
сам опрос в `end_date`; бот дожидается подтверждения `closed=true`.
Давайте достаточно времени между активацией и дедлайном (больше часа).
Если книга не настроена, журнал явно сообщает о пропуске.

## Пример первого голосования

Не запускайте пример, пока не зададите настоящий будущий дедлайн и текст.
На каждый новый запуск истории используйте **новый quest_id**. Этапы внутри
одного квеста должны иметь уникальные ID; циклы с повторным входом в уже
проведённое голосование не поддерживаются.

Лист «Квесты» сохраняет прежние колонки:

| quest_id | название | статус | текущий_этап | peer_id | описание |
|---|---|---|---|---|---|
| forest01 | Развилка | draft | choice | 2000000002 | Выбор пути |

Когда всё готово, замените `draft` на `active`. Для запуска без голосования
по-прежнему используется этап `start` и прежние пороги.

В листе «Этапы» нужны три строки:

| Поле | Голосование | Ветка леса | Ветка гор |
|---|---|---|---|
| quest_id | forest01 | forest01 | forest01 |
| stage_id | choice | forest | mountains |
| тип | vote | finish | finish |
| текст | Сычики встретили развилку. Куда идём? | Сычики отправились в лес. | Сычики выбрали горную тропу. |
| порог_мышей | пусто | пусто | пусто |
| порог_процентов | пусто | пусто | пусто |
| дедлайн_ISO | будущая дата с часовым поясом | пусто | пусто |
| успех_этап | пусто | пусто | пусто |
| провал_этап | mountains | пусто | пусто |
| варианты_JSON | JSON ниже | пусто | пусто |
| ничья_этап | пусто | пусто | пусто |

`варианты_JSON`:

```json
[{"текст":"Пойти в лес","этап":"forest"},{"текст":"Подняться в горы","этап":"mountains"}]
```

Дедлайн, например: `2026-11-20T18:00:00+03:00` (замените на нужный).

## Результат и продолжение

- От 2 до 10 разных вариантов. Вопрос — до 255 символов, вариант — до 100.
- Выигрывает вариант с максимальным числом голосов VK. ID ответов сохраняются
  при создании; изменение их порядка в ответе API не меняет выбранную ветку.
- При ничьей выбирается `ничья_этап`, если он задан. Иначе первый из
  лидирующих вариантов в JSON. Правило публикуется в объявлении.
- При отсутствии голосов используется обязательный `провал_этап`.
- Тип `finish` завершает квест, обычный этап продолжает историю.
  Между двумя голосованиями нужен отдельный обычный этап.
- Итоги не применяются, пока VK не подтвердит закрытие и прежние параметры
  опроса. При ошибке API квест остаётся на текущей ветке.

Состояние сохраняется в автоматически создаваемом `_QuestPolls`:
quest_id, stage_id, отпечаток настроек, статус, owner_id, poll_id,
ID ответов, результаты, признак закрытия и ID сообщения. Токенов там нет.
Не меняйте вопрос, варианты, чат и дедлайн уже созданного опроса; для нового
опроса используйте новый этап, а для нового запуска истории — новый quest_id.
Отметка `ready` сохраняется до отправки. Повтор использует тот же poll_id
и стабильный `random_id` сообщения; исходящее подтверждается после проверки
вложения. Для обычных сюжетных сообщений остаётся прежняя очередь отправки.

## Если создание опроса оборвалось

У `polls.create` нет ключа идемпотентности. Перед запросом записывается статус
`creating`. При явном отказе API он становится `retry` и создание можно
повторить после исправления прав токена. При таймауте, непонятном ответе или
неподтверждённой записи в Google повторное создание блокируется: опрос уже
мог появиться на стороне VK. Создавать новый наугад нельзя.

Если опрос существует, восстановите привязку защищённым запросом:

```json
POST /quest-poll-recover
X-Schedule-Secret: <секрет из Render>
{"questId":"forest01","stageId":"choice","ownerId":123,"pollId":456}
```

Бот сам прочитает этот опрос через `polls.getById` и сверит вопрос, варианты,
режим одного ответа и дедлайн с таблицей. Только после совпадения сохранит ID.
Затем снова запустите `quests`. Если опрос не создан, сначала убедитесь в этом
в VK; для новой попытки после неопределённого результата нужен отдельный этап
с новым stage_id. Защищённый endpoint не умеет сбрасывать creating вслепую.
